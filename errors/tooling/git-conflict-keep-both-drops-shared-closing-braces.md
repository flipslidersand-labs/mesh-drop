## 症状

2 つの PR がそれぞれテストファイル末尾に関数を追記しており、rebase でコンフリクトした。
`<<<<<<< HEAD (A) ======= (B) >>>>>>>` を正規表現で「A の後に B」へ置換したところ、ビルドが壊れた。

```text
roundtrip_test.go:453:6: expected '(', found TestRoundTrip_ResumeAfterReceiverError
```

## 原因

git は両側に共通する末尾行（関数の閉じ `\t}\n}\n`）をコンフリクト区間の外に出す。
そのため区間内の A は閉じ括弧を欠いた状態で終わっており、単純連結すると A の関数が閉じないまま
B の関数定義が始まる。

## 解決策

連結後に A の末尾へ欠けた閉じ括弧を補い、`gofmt -l` / `go vet` でパースを確認した。

## 予防

- 「両方採用」を機械的に行ったら、必ずその場で `gofmt -l <file>` と `go vet` を通す。
- 末尾追記が衝突しやすいテストファイルは、PR ごとに別ファイル（`xxx_test.go`）へ分けると衝突自体が起きない。
